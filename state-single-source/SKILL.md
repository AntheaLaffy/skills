# 状态设计与单一事实来源

## 先分清状态和规则

- **状态**（会变）：写到第几章、下一项、卷数、字数、覆盖率、版本、里程碑日期。
- **规则**（少变）：文风、流程、标准、架构约束。

状态必须有唯一来源 + 生成 + 校验；规则写进规范文档，规范里不写“现在到第几”。

## 与 project-maintenance 的分工

| 归本技能 | 归 `$project-maintenance` |
|---|---|
| 进度/统计/清单类数字的唯一来源与生成 | 代码地图、导航路由 |
| 派生文本的生成块、幂等、漂移校验 | 契约/UI/推理验证，退役与临时层清理 |
| “哪个数字不要手改”的规则落地 | 审查指纹记录（`.project-maintenance/state.json`） |

两者都要求“别留两份”，但对象不同：本技能管**数值被抄了几份**，maintenance 管**代码/地图/测试是否还对应**。项目已有指纹脚本时直接复用，不要为状态再造一套记录。

## 症状对照

| 症状 | 真实问题 |
|---|---|
| 同一个数字出现在 N 个文件 | 必然漂移，差距随时间拉大 |
| “当前状态”是手写段 | 更新靠记忆，漏一处就两套档案 |
| 文档互相矛盾（43 章 vs 42 章、176 vs 175） | 缺结构校验，光改文本修不掉 |
| 改一处要改五处 | 派生关系没建模 |
| 章号断档/重复没人发现 | 只比文本，不校验结构 |

## 三步架构

1. **事实源**：只留“人本来就写、且最少”的输入。优先复用已有结构（目录名、文件名、标题行），**不要另建一份中央清单**再同步。
2. **计算器**：一个脚本解析事实源 → 模型 → 派生文本。幂等、无网络、无第三方依赖。
3. **生成块**：文档里用注释夹住派生段，只重写块内：

```markdown
<!-- BEGIN generated:status -->
- 3 卷 42 章；下一章 43《复试线》
<!-- END generated:status -->
```

标记要渲染后不可见（HTML 注释）；放在代码块里也行，只要脚本能匹配。

## 校验比生成更重要

`--check` 至少覆盖：编号连续、区间与内容一致、文件名与内容标题一致、孤儿条目（有实物没条目 / 有条目没实物）、重复定义、生成块过期。非 0 退出，接进发布或提交脚本。

## 落地顺序（一小时内可完成）

1. **扫描**：grep 出所有重复数字，列出“谁抄了谁”。
2. **定源**：选最难造假的输入——文件名/标题行优先于手写清单。
3. **写计算器**：约 80 行，dataclass + 解析 + 文本块 + check。
4. **验收**：把现有手写段落**原样包进标记**后跑生成，输出应与原文逐字相同。不同就让生成器先复现原文，再决定改文案还是改模板。这一步比任何测试都灵。
5. **接守卫**：把 `--check` 放到 publish/commit 前；做负向测试（手改一个块 → 退出 1 → `--write` 复原）。
6. **清副本**：删掉其余手写副本，并在规范文档里写一句“哪个数字不要手改”。

## 吃过的亏

- 不要新建中央 JSON/表格当事实源，除非它本来就有人工维护需求；从已有产物派生最省。
- 生成器只重写块内。块外的手写句（“下一章见 44”）也会漂 → 要么纳入块，要么改写成不含量。
- `.strip()` 会吃掉块首行缩进 → 只 `strip("\n")`。
- 空块替换会灾难：`text.replace("", body)` 会把内容插进每个字符之间 → 用正则整块替换。
- 文档里的“118 行”“176 章”这类体量数字别手写，要么生成，要么删。
- 计划编号不能只改一卷：下游卷、人物卡、研究文档里的章号引用要一起平移，并用 check 兜住（曾合并一卷导致缺第 61 章）。
- 派生文本要保留人写的语气；改文案改模板，不要改生成块。

## 反模式

- 用全库 grep-and-replace “同步”数字（下次还得再来一遍）
- 只做生成不做校验（编号断档查不出来）
- 把派生数值复制到第三处（链接可以，抄数值不行——二手派生会漂两次）
- 规则和状态混在同一段（半年后没人分得清哪个是约束）

## 验证（只验派生链）

- `--write` 幂等：连跑两次，第二次 0 更新。
- 正确状态 `--check` 退出 0；手改一个块退出 1。
- 生成文本与改造前手写文本事实一致。
- 下游构建/发布仍通过，且产物统计与生成块一致。

产品契约、UI、推理正确性不在这里验，那是 `$project-maintenance` 的事；本技能只证明“文档里的数是从事实源算出来的”。
